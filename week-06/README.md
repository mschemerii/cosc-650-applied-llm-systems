# Week 6 — Query Transformation and Re-ranking

## Assignment

This week extends the Week 5 RAG retrieval pipeline on the same 16 chunks and same 10 frozen test queries. The experiment adds a query-side transformation and a ranking-side re-ranker, then measures whether either change actually helps.

### Pipeline

- **Baseline:** `sentence-transformers/all-MiniLM-L6-v2` + FAISS cosine retrieval, `k=3`
- **Query transformation:** two Gemini `gemini-3.5-flash-lite` rewrites generated in one call per query
- **Transformation-only stage:** reciprocal-rank fusion over the original query and both rewrites, measured before reranking
- **Re-ranking:** local `cross-encoder/ms-marco-MiniLM-L-6-v2` over fused candidates
- **Metrics:** Precision@3, Recall@3, Hit@1, MRR, nDCG@3, and per-query deltas for baseline, transformation-only, and final reranked retrieval

MiniLM is retained as the Week 5 baseline because the saved Week 5 run ranked the gold chunk first for 8/10 queries, while MPNet was already 10/10. That gives this experiment room to measure whether transformation and re-ranking improve ranking rather than starting from a ceiling.

## Measured results

| Metric | Baseline | Transformation only | Final reranked |
| --- | ---: | ---: | ---: |
| Precision@3 | 0.333 | 0.333 | 0.333 |
| Recall@3 | 1.000 | 1.000 | 1.000 |
| Hit@1 | 0.800 | 0.700 | 1.000 |
| MRR | 0.900 | 0.850 | 1.000 |
| nDCG@3 | 0.926 | 0.889 | 1.000 |

The query transformation by itself reduced MRR by 0.050 versus baseline. The cross-encoder reranker then improved final MRR by 0.100 versus baseline and raised Hit@1 from 0.800 to 1.000.

### Query-type result

The notebook groups cases by retrieval behavior at baseline:

- 8 queries already had the gold chunk at rank 1. Transformation produced a mean MRR delta of -0.062 for this group.
- 2 queries did not have the gold chunk at rank 1. Transformation produced no MRR improvement, but reranking improved both cases by +0.500 MRR on average.

### Required failure case

Q04 regressed after transformation. Its gold chunk moved from rank 1 to rank 2, producing an MRR delta of -0.500. The final cross-encoder reranker restored the gold chunk to rank 1. This separates the transformation failure from the later reranking repair.

## Free-tier behavior

The notebook checks `GEMINI_API_KEY` in Colab Secrets first, then the environment, then a local JupyterLab `.env` file. It generates both rewrites for a query in one Gemini request. Cache entries are accepted only when they contain two unique, non-empty rewrites; otherwise the query is regenerated. Successful rewrites are cached immediately, and 429 responses use retry/backoff handling.
